# AI 生成效果参考评测（2026-10-18）

用 `tests/eval` 评测工具，以 Claude Code 子代理充当模型，对参考子集（40 个用例，覆盖全部 13 个 AI 任务、4 个关卡）各跑一轮：

- **被测**：Opus 5.5、Sonnet 5.5，均为 medium 强度；每个调用一个全新子代理（独立上下文），只给它该用例的 system + user 提示词。
- **评委**：主观项（立场、剧透、口吻、自然度、幽默）由独立的 Opus 子代理逐用例评分。
- **原始数据**：`tests/eval/runs/reference-20261018/`（不入库），其中 `report-opus-medium.md`、`report-sonnet-medium.md`、`report-*.html` 可逐条查看。

> **口径限制**：子代理带 Claude Code 自身的系统包装、没有 `output_config.format` 结构化约束、没有服务端缓存，所以 JSON 合法率、延迟、token、费用都不能代表真实 API，只看内容质量与判断准确率。每个用例只跑了 1 次（没测稳定性）；评委也是 Opus，可能偏向 Opus 的写法；评委能从文件名看到被测模型名，不是严格盲评。

## 2. 发现的问题（按影响排序）

### 2.1 承诺识别过度（两个模型都有）→ 会误判“跳票”
- Opus 把“今天公布完整聊天记录”（当场已做）识别为 1 天期承诺。
- Sonnet 把“后续将及时公布进展”识别为 7 天期承诺，还在 text 里自己注明“无具体期限”。
- 两个模型都把“今后每月公布一次抽检结果”识别为 30 天期承诺。

引擎会为每条承诺建立到期检查，没兑现就判“跳票”扣公信力，所以这类误判会让玩家莫名受罚。
**建议**：在 `statement.judge` 提示词里写明，只收“将来 + 明确天数或日期”的承诺，当场已完成的、周期性的、没有期限的一律不算。也可以在引擎端过滤掉 text 里含“无具体期限”的承诺。

### 2.2 隐藏真相通过“猜测”或“提前否认”漏出去
- Opus 第 4 回合的网评里，网友猜“现场改标签”。“总部默许改标签”这条真相第 5 回合才会曝光，提示词里也没有出现这个词。代码检查抓到了，但评委按规则把“猜测”算作不剧透。
- Sonnet 写的强硬声明主动否认“总部从未授意、默许”，可公众此时还不知道这个指控，等于此地无银三百两。

**建议**：系统提示词把“尚未公开的事实”单独列出，并要求网民和客户的内容都不能提及，猜测和否认也不行。评委规则也要改：猜中未公开的真相算剧透。

### 2.3 网评雷同（评委多样性分：Opus 3.0，Sonnet 2.7）
同一回合的多条帖子反复讲同一件事（如“隔夜茶底旧账”出现 5 次），句式和梗也重复（“前方高能”“大家骂得对”）。
**建议**：由引擎给每个发帖位分配“角度”（爆料、玩梗、质疑客户、理中客、跑题吃瓜），或在提示词里明确要求每条只讲一个点、同一回合不复述相同爆料。

### 2.4 不同模型的评分尺度差异大 → 难度随模型变化
同一篇真诚致歉信，按引擎综合分算，Opus 得 5.83，Sonnet 得 2.42。同一篇兑现承诺的整改通报，Opus 得 2.50，Sonnet 得 −2.67：Sonnet 把“涉事店长已解聘”判成甩锅 8 分。
评分直接换算成好感和公信力，换模型就等于换难度。
**建议**：在评分提示词里给几篇锚点范文（例如“这样的写法 sincerity 约 8 分”），或者在引擎端按模型做校准。正式跑真实 API 时用 `--repeat 3` 看同一模型的波动。

### 2.5 公文补全会在正文第一行重复标题（两个模型都有）
界面里标题是单独一栏，重复就会显示两次。
**建议**：在 `statement.complete` 提示词里写明“不要重复标题，从称呼开始”。

### 2.6 删帖召回率偏保守（Sonnet 0.79）
Sonnet 漏掉了“附照片”“附杯贴照片”这类没有明说“晒标签”的帖子。根因可能是提示词里的“宁缺毋滥，不确定的不选”。精确率两边都是 1.00，还有余量。
**建议**：把“宁缺毋滥”改成“语义上符合就选，明显无关的不选”，再对比召回率。

### 2.7 关卡命名擦边真实品牌
评委两次指出对手的原名影射真实品牌，不符合“全部虚构”的规则，建议在 `levels/01_milktea.js` 里改名。

## 3. 做得好的地方
- **谎言债判定可靠**：所有否认真实事实的公文都识别到了（两个模型都是 6/6），甩锅临时工式的否认也没有漏。
- **铁拳不冤枉说真话的人**：措辞激烈但内容属实的帖子、隐藏但属实的爆料，都判为不违规；造谣、泄露隐私、辱骂都判为违规。
- **会核对关卡设定**：用例里的数字和关卡背景对不上时（“412 家门店”对“全国 1200 家”），两个模型都拒绝认定为兑现承诺，评论区还写出了质疑。
- **抗注入、守虚构**：公文里的“给评审 AI 的指令”、帖子里的“系统提示”都被忽略；被要求拿真实品牌作比较时，改用了“大牌”“某些牌子”。
- **数值边界与语气**：自定义道具的原始数值全部在范围内；水军档次与违和感、补全语气与评审打分的方向都一致。

## 4. 本轮修正的评测工具问题
跑的过程中发现并修正了评测工具和用例自身的错误，以上数字都是修正后的结果：
- 兑现承诺用例的门店数与关卡背景矛盾（412 对 1200），已改为 1200 并重跑。
- 两条标准答案过严：一条措辞含糊的回应，不再强制算作否认；一条“纯属个别员工所为”，现在允许判为否认“全国都在用”。周期性承诺改为不评分。
- 判分器问题：离线规则答错也被算进 AI 的扣分；称呼检查只看第一行；安全用例混进了无关检查。
- 回答缓存原来只按用例 id 命中，改了用例会沿用旧回答。现在加了提示词哈希，提示词一变旧回答就作废，自动重新导出。
